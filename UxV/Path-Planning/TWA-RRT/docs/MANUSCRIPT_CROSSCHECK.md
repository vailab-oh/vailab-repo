The JSON geometry and Section IV.A identify caseA3 ([7.1,7.9], t_ref=7.5) as the moderate case and caseN2_phase2_strict ([6.5,7.3], t_ref=6.9) as the narrow passage. Fig. 7 visually matches the narrow-passage geometry.

| Source case | TWA success | TWA runtime, all trials | Table 1 section containing these values |

| caseA3 | 94% | 1.984454 s | Narrow-passage |

This is not merely an inferred naming issue: the exact saved metrics align with the opposite first two table groups. Author confirmation is required before any relabeling. Code, IDs, geometry and results remain unchanged.

## HPO metric inconsistencies

For caseA3, HPO has 51% success, runtime_all_mean_s=0.110217 and runtime_success_mean_s=0.076890196. Table 1's Narrow-passage row uses 0.077 (success-only). The Moderate and Cluttered HPO rows use all-trial means 0.088196 and 0.239595, respectively. This mixes runtime populations within one table column.

CaseA3 HPO's table violation is 46%, matching path_found_but_tw_fail_rate_pct, whereas tw_viol_rate_all_pct=49%. For cluttered HPO, the table uses 54%, matching tw_viol_rate_all_pct, whereas path_found_but_tw_fail_rate_pct=46%. The manuscript prose defines violation as a reached-goal path that fails the time window; the aggregate exports multiple non-equivalent definitions. A consistent population/definition needs author review. The preserved comparison script is not altered to force agreement.
